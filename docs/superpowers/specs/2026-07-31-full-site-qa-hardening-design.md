# 卡密系统全站验收加固设计

## 背景

近期线上验收连续暴露了几类问题：操作审计显示原始时间和英文枚举、对象用户为空、管理员页面混入发卡用户数据、设备名称/型号/设备 ID 为空、发卡用户批次页规格字体和操作区不一致。这些问题说明当前测试更擅长证明接口存在、源码包含字段、主页面可打开，但没有系统证明“带真实业务数据的每个角色页面在浏览器里正确显示”。

## 目标

- 让前端 router、侧边栏菜单、页面契约、生产浏览器巡检形成闭环，新增或遗漏页面时测试失败。
- 为管理员、发卡用户、使用用户/SDK、匿名访问建立角色隔离矩阵。
- 为审计、额度流水、应用归属、批次规格、设备上报建立业务语义矩阵。
- 将 UI 验收从页面可打开升级到 desktop/mobile 下无空白、无遮挡、无溢出、无操作按钮缺失。
- 线上验收报告不得输出 Secrets、服务器密码、token、cookie、完整卡密或敏感凭证。

## 非目标

- 不重构业务架构，不改变现有 FastAPI/Vue 技术栈。
- 不修改真实支付配置的长期业务语义；生产 QA 如需临时数据，必须带唯一前缀并可清理。
- 不移除旧软件兼容接口，除非用户明确要求。

## 覆盖设计

### 路由覆盖

测试应自动比较 `admin/src/router/index.js`、布局菜单、`scripts/page_contracts.py`、`scripts/production_e2e_browser_qa.py`。任何主页面路由存在但没有页面契约或浏览器巡检条目，都应失败。

动态页面不能跳过，必须由生产 QA 先创建或查询上下文 ID 后访问，例如发卡用户详情、发卡用户作用域批次、应用接口配置。

### 页面契约

每个页面契约至少描述：

- 路由和组件文件。
- 关键标题、筛选区、统计卡、表格列、空状态。
- 行操作按钮和弹窗入口。
- 时间格式、状态文案、资源类型、操作类型等中文显示规则。
- desktop/mobile 下必须稳定的布局区域。

### 业务语义

重点补充这些矩阵：

- 操作审计：操作人、对象用户、资源类型、资源 ID、摘要、结果、详情弹窗、北京时间格式。
- 发卡额度流水：管理员代操作显示管理员，发卡用户自操作显示发卡用户。
- 应用归属：管理员应用信息只显示管理员自建应用；发卡用户后台只显示自建和授权应用。
- 使用用户：管理员使用用户管理只显示管理员应用下的用户；发卡用户详情页显示该发卡用户作用域用户。
- 设备管理：SDK 上报设备名称、设备型号、设备 ID 后，管理员和发卡用户可见列表均显示非空。
- 批次规格：管理员和发卡用户的规格表格列、字体、徽标、操作区保持一致。

### 视觉验收

生产浏览器巡检应覆盖管理员、发卡用户、公开页的 desktop 和 mobile 视口。重点页面应保留截图和局部视觉基线：

- 操作审计
- 设备管理
- 使用用户管理
- 应用信息
- 发卡用户详情
- 管理员作用域批次
- 发卡用户批次管理
- 发卡额度流水

巡检应捕获 JavaScript 异常、console error、失败网络请求、错误 toast、页面空白、水平溢出、重复控件、标题遮挡、按钮缺失、表格操作区错位。

## 验收标准

- `python -m pytest -q` 通过。
- 前端构建通过。
- 路由覆盖测试无遗漏。
- 页面契约覆盖所有主页面。
- 生产 `/health`、`/docs/api`、`/api/v1/docs/interfaces` 返回 200。
- 重点业务矩阵通过。
- 生产浏览器巡检无 P0/P1 问题。
- 报告和日志不包含敏感信息。
